The D1 adaptor receives a Worker database binding. It does not open a network connection or require a separate database driver.

## Configure the binding

Add your provisioned database to `wrangler.toml`:

```toml
[[d1_databases]]
binding = "DB"
database_name = "my-database"
database_id = "YOUR_DATABASE_ID"
```

Install `zodbase` and `zod` in the Worker project. Pass `env.DB` to the adaptor from your Worker handler:

```ts
import type { D1Database } from "@cloudflare/workers-types";
import { Database } from "zodbase";
import D1Adaptor from "zodbase/adaptors/d1";

export function connectDatabase(env: { DB: D1Database }) {
  return new Database({ adaptor: new D1Adaptor({ driver: env.DB }) });
}
```

Use generated Worker binding types or install `@cloudflare/workers-types` for the type import above. Cloudflare owns the binding lifetime; there is no driver connection to close.

## Write-only transactions

`db.transaction()` collects statements and submits one `driver.batch()` after the callback succeeds. Writes are queued during the callback, so do not expect to read their results before the batch runs.

- Inserts, updates, and deletes can be queued.
- Reads, `WITH` statements, and `RETURNING` are rejected inside the transaction.
- Do not call `.selectMutated()` inside a D1 transaction.
- Nested transactions are rejected.
- If the callback throws, the collected statements are not submitted.

Outside a transaction, row-returning statements use `all()` and other statements use `run()`. `updateMany` uses D1's batch API.

## Schema changes

The adaptor shares [SQLite schema logic](/adaptors/sqlite/). Do not call `syncTable` inside a write-only transaction: synchronization inspects existing schema. Validate schema changes in your Worker/D1 environment; the package's driver-interface tests do not replace that integration check.
